# دليل ATTACKDNA للمطوّر

> مرجع شامل: أين الملفات، كيف تشغّل المشروع، كيف يسير النظام من دخول المستخدم إلى المخرجات،
> وأين تعدّل كل شيء. اقرأه مرة، وارجع له كل ما احتجت تطوّر.

---

## ١. تشغيل المشروع في ٣ دقائق

```bash
cd attackdna

make all      # يبني البيئة + ينزّل البيانات + يعبّي الذاكرة  (مرة واحدة، ~٥ دقائق)
make demo     # يفتح الواجهة على http://localhost:8501
```

**ما تحتاج مفتاح API ولا إنترنت** بعد `make all`. النظام كامل يشتغل بالوضع الحتمي (rule-based).

### باقي الأوامر

| الأمر | وش يسوي | متى تستخدمه |
|---|---|---|
| `make demo` | يفتح الواجهة | العرض والتجربة |
| `make api` | يفتح الـ API على `:8000/docs` | لو المحكّم طلب يشوف الـ API |
| `make test` | ٩٣ اختبار | **بعد كل تعديل** |
| `make eval` | يقيس الدقة بالأرقام | بعد أي تعديل على الاستخراج |
| `make reset` | يمسح القاعدة والذاكرة ويعيد التعبئة | لو خربت البيانات |
| `make data` | يعيد تنزيل MITRE و CISA KEV | لتحديث قواعد المعرفة |

### تشغيل بدون Makefile (ويندوز)

```bash
python -m venv .venv
.venv\Scripts\pip install -r backend\requirements.txt
copy .env.example backend\.env

.venv\Scripts\python scripts\download_mitre.py
.venv\Scripts\python scripts\process_mitre.py
.venv\Scripts\python scripts\process_cti.py
.venv\Scripts\python scripts\download_kev.py
.venv\Scripts\python scripts\process_kev.py
.venv\Scripts\python scripts\seed_memory.py --reset

.venv\Scripts\streamlit run frontend\app.py
```

### لو صار خطأ

| المشكلة | الحل |
|---|---|
| `Knowledge base missing` | `make data` |
| `No similar incidents in memory` | `make seed` |
| الواجهة تطلع فاضية | `make reset` |
| بطيء أول تشغيل | طبيعي — يحمّل نموذج MiniLM (~80MB) مرة واحدة |
| تعديل ما ظهر | Streamlit يعيد التحميل تلقائيًا؛ لو ما ظهر اضغط `R` في المتصفح |

## ٣. سير العمل: من دخول المستخدم إلى المخرجات

### الرحلة كما يراها المستخدم

```
المستخدم يفتح http://localhost:8501
        │
        ▼
① يختار سيناريو جاهز، أو يرفع ملف، أو يلصق تقرير حادثة
        │
        ▼
   يضغط زر  [ Analyze incident ]
        │
        ▼
   ⏱️ ٠.٤ ثانية
        │
        ▼
تظهر ٦ أقسام دفعة واحدة في نفس الصفحة ⬇
```

### ما يحدث داخليًا (خط الأنابيب)

كل شيء يمر عبر دالة واحدة: **`analyze()`** في `backend/app/pipelines/analyze.py`.

```
        نص التقرير الخام (فيه أسماء، إيميلات، IPs)
                        │
┌───────────────────────▼────────────────────────────────────┐
│ ① sanitizer.sanitize()                       الخصوصية      │
│   يشيل: إيميلات، IPs، دومينات، أسماء، شركات، أجهزة،        │
│         حسابات، هواتف، أرقام هوية، بطاقات، مفاتيح API      │
│   يبقي: CVE, T####, hashes   ← بصمة الهجوم مو هوية الضحية  │
│   ثم verify_clean() يمسح مرة ثانية للتأكد    → PASS/FAIL   │
└───────────────────────┬────────────────────────────────────┘
                        │  النص المنقّى فقط (الخام يُرمى)
┌───────────────────────▼────────────────────────────────────┐
│ ② dna_extractor.extract_dna()              بصمة الهجوم    │
│                                                             │
│   ├─ نوع الهجوم + طريقة الدخول  (منفصلين!)                 │
│   ├─ mitre_mapper  ← تقنيات وتكتيكات ATT&CK + الدليل        │
│   ├─ kev_enricher  ← CVEs + هل مستغلة فعليًا؟               │
│   ├─ ioc_extractor ← مؤشرات قابلة للمشاركة / محذوفة        │
│   ├─ attribution   ← تشابه مع جهات تهديد معروفة            │
│   ├─ القطاع + الأثر + الخطورة                               │
│   └─ validate_dna() ← فحص المخرج قبل ما يكمل                │
└───────────────────────┬────────────────────────────────────┘
                        │  Attack DNA
┌───────────────────────▼────────────────────────────────────┐
│ ③ similarity.find_similar_incidents()      الذاكرة        │
│   مرحلتين:                                                  │
│   أ. استرجاع دلالي  ← ChromaDB يرجّع أقرب البصمات           │
│   ب. إعادة ترتيب بنيوي ← تقنيات مشتركة، تكتيكات، نوع،       │
│                          طريقة دخول، CVEs، قطاع            │
│   النتيجة = ٠.٤٥ × دلالي + ٠.٥٥ × بنيوي + **سبب كل تطابق** │
└───────────────────────┬────────────────────────────────────┘
                        │  حوادث مشابهة
┌───────────────────────▼────────────────────────────────────┐
│ ④ mitigation_memory.recall_mitigations()   ما نجح سابقًا  │
│   ثلاثة مصادر منفصلة ومعلّمة:                               │
│   • recalled  ← ما سوّته منظمتكم فعلًا (مع مصدره)           │
│   • framework ← mitigation رسمية من MITRE (M####)          │
│   • suggested ← ضابط أساسي يسدّ الفراغ                      │
└───────────────────────┬────────────────────────────────────┘
                        │
┌───────────────────────▼────────────────────────────────────┐
│ ⑤ simulator.build_simulation()             محاكاة آمنة    │
│   تمرين tabletop دفاعي: حقن + الكشف المتوقع + مصدره +      │
│   نقطة القرار + إجراءات الاستجابة + معايير النجاح          │
│   ❌ صفر أوامر أو payloads — واختبار يثبت ذلك              │
└───────────────────────┬────────────────────────────────────┘
                        ▼
                   المخرجات الست
```

### الفرق بين `analyze()` و `ingest()`

| | `analyze()` | `ingest()` |
|---|---|---|
| يشغّل المراحل الست | ✅ | ✅ |
| **يحفظ في القاعدة** | ❌ | ✅ |
| **يضيف للذاكرة** | ❌ | ✅ |
| متى | الوضع الافتراضي | لما تفعّلين "Commit to memory" |

**ليه الفصل؟** المستخدم يشوف وش راح ينحفظ **قبل** ما ينحفظ.

## ٤. المخرجات الستة بالتفصيل

### ① Privacy Shield
- النص المنقّى، والحذوفات **ملوّنة بالأحمر**
- عدّاد: كم قيمة انحذفت، من كم نوع
- **PASS/FAIL** من فحص مستقل ثانٍ
- جدول تدقيق: كل رمز + نوعه + القيمة الأصلية **مقنّعة** (`jo***se`)

### ② Attack DNA
```
RANSOMWARE | finance | initial-access:T1566.002 > execution:T1059.001
> lateral-movement:T1021.002 > impact:T1486 | impact:data_encrypted+...
```
- نوع الهجوم، طريقة الدخول، القطاع، الخطورة
- جدول تقنيات ATT&CK **مع الدليل النصي لكل تقنية** وثقتها
- CVEs مع حالة CISA KEV والإجراء المطلوب
- مؤشرات: قابلة للمشاركة (hashes، امتدادات، بروتوكولات) مقابل محذوفة (بالعدد)
- تشابه مع جهات تهديد: `BlackByte 88% [notable]`

### ③ Similar Incidents
لكل حادثة: نسبة مجمّعة + دلالية + بنيوية، **وأسباب التطابق**:
```
0.77 — Ransomware via phishing link — regional bank
       - 4 shared ATT&CK techniques: T1059.001, T1486, T1490, T1566.002
       - Same attack type: ransomware
```

### ④ Mitigation Memory
مجمّعة حسب مرحلة الاستجابة (Detect → Contain → Eradicate → Recover → Harden):
```
[recalled · used in 5 past incidents · avg effectiveness 92%]  Isolate affected endpoints
[baseline control]                                             Alert on SMB service creation

Official MITRE ATT&CK mitigations
  M1018  User Account Management    covers 4: T1021, T1078, T1490, T1566.002
```

### ⑤ Safe Simulation
- بطاقة السيناريو (نفس شكل الموك في عرضكم)
- حقن لكل مرحلة + الكشف المتوقع + مصدره + نقطة القرار + إجراءات الاستجابة
- معايير النجاح + تنويه السلامة

## ٦. أعلى ٥ تحسينات تستاهل وقتك

مرتّبة حسب (الأثر ÷ الجهد):

### ١. زيدي حوادث في الذاكرة  ⏱️ ١٥ دقيقة للحادثة · أثر عالي جدًا
كل حادثة تقوي الذاكرة، والذاكرة **هي المنتج**. ١٤ الحين — لو صارت ٢٥ الديمو يصير أقوى بوضوح.

في `data/seed/incidents.json` أضيفي:
```json
{
  "title": "عنوان وصفي",
  "occurred_at": "2025-08-14",
  "text": "التقرير كامل — اتركي الأسماء والإيميلات والـ IPs، النظام ينقّيها",
  "mitigations": [
    {"action": "الإجراء اللي انعمل", "category": "contain",
     "effectiveness": 0.9, "notes": "ليه نجح أو فشل"}
  ]
}
```
`category` واحدة من: `detect` / `contain` / `eradicate` / `recover` / `harden`

ثم: `make reset`

### ٢. وسّعي مجموعة القياس  ⏱️ ٢٠ دقيقة للحالة · أثر عالي
٨ حالات تكشف التراجع، ما تثبت التعميم. لو وصلتيها ١٥ تقدرين تقولين رقم أقوى قدام المحكمين.

### ٣. حسّني استدعاء التقنيات  ⏱️ ٥ دقائق · أثر متوسط
شغّلي `make eval` وشوفي قسم "Cases worth reviewing" — يقول لك أي تقنيات فاتت. أضيفي العبارة في `ALIASES` وأعيدي `make eval`. حلقة تحسين سريعة جدًا.

### ٤. جرّبي مفتاح Claude API  ⏱️ ٥ دقائق · أثر متوسط
حطي المفتاح في `backend/.env` ثم `make eval --use-llm` وقارني. لو تحسّن، اذكري الرقمين في العرض ("يشتغل بدون AI، ويتحسّن معه").

### ٥. تقارير عربية  ⏱️ ساعتين · أثر عالي جدًا في التحكيم المحلي
طبقة الـ regex إنجليزية اليوم. إضافة أنماط عربية للأسماء والشركات = ميزة تنافسية واضحة في سياق سعودي.

## ٧. قواعد أثناء التعديل

1. **بعد أي تعديل: `make test`** — ٩٣ اختبار تكشف الكسر فورًا
2. **بعد تعديل الاستخراج: `make eval`** — تشوفين هل تحسّن ولا ساء بالرقم
3. **بعد تعديل `incidents.json`: `make reset`** — الذاكرة تُبنى وقت التعبئة
4. **لا تكسرين الخصوصية:** `raw_text` لازم يبقى `NULL` افتراضيًا، والـ embedding ما يدخله أي معرّف. فيه اختبارات تحرس هذا.
5. **اشتغلي على فرع:** `git checkout -b my-changes` قبل التعديل

## ٨. أسئلة متوقعة من المحكمين

| السؤال | الجواب |
|---|---|
| "كيف أتأكد إن التنقية ما تفوّت شي؟" | فحص مستقل ثانٍ `verify_clean()` + ١٣ اختبار + صفر تسريبات على كل حالات القياس |
| "استخدمتوا AI فعلًا؟" | نعم — MiniLM embeddings للبحث الدلالي، وطبقة LLM اختيارية. والحتمية مقصودة في الخصوصية: regex ما "يقرر" يسرّب IP |
| "ليش ما تولّدون هجوم حقيقي؟" | تمرين tabletop يختبر هل الكشف والاستجابة يشتغلون — وهذا سؤال الـ SOC. توليد هجوم شغّال ما يجاوب على أي سؤال عندهم |
| "التشابه رقم من وين؟" | مرحلتين: تشابه دلالي + تطابق بنيوي على تقنيات ATT&CK. نعرض الرقمين منفصلين وأسباب كل تطابق |
| "الجهة اللي حددتوها أكيدة؟" | لا — ونقولها صراحة. أعلى تصنيف "notable"، ومعاه تنويه إن التشابه السلوكي ≠ إسناد |
| "وش دقة النظام؟" | ١٠٠٪ نوع/قطاع/ناقل، F1 = ٨٤٪ لتقنيات ATT&CK، ١٠٠٪ استرجاع@1، على ٨ حالات مصنّفة. العدد صغير والتوسيع أول بند في Future Work |
